1. PROJECT OVERVIEW
================================================================

1.1 He thong la gi?
-------------------
IX Metaverse Contract Management System — quan ly tat ca "tuong tac dua tren
dong thuan" (contracts) giua users trong metaverse IX.

  Vi du contract:
    RPS (Keo-bua-bao):  User vs User, dat cuoc point theo ket qua
    Work Reward:         Thanh toan khi hoan thanh cong viec (Worker vs Client)
    Tournament:          Thu phi tham gia va chia giai thuong (Participant vs Organizer)
    Custom:              Template tuy chinh do Admin dinh nghia

1.2 Phase Plan
--------------
  Phase 0 (HIEN TAI)  ->  Phase 1          ->  Phase 2            ->  Phase 3
  Off-chain (Supabase)    On-chain MegaETH     IX Economic Token      DAO Governance
  IX Points / Free Pts    USDT                 ERC-20 Token           Governance Token

  Phase   Thanh toan                Quan ly              Muc tieu
  ------  ------------------------  -------------------  --------------------------------
  0 (now) IX Points / IX Free Pts  Off-chain (Supabase) UX validation, user acquisition
  1       USDT tren MegaETH        Smart contracts      On-chain migration
  2       IX Economic Token ERC-20 Smart contracts      Token economy
  3       Economic + Gov Token     DAO                  Community governance

  FE dang build cho Phase 0. DB schema thiet ke san de map 1:1 sang smart contract Phase 1.

2.1 Tong quan
-------------

  contract_templates   <-- Admin tao template (RPS, Work Reward...)
        |
        | 1 template -> N instances
        v
  contract_instances   <-- Moi tran dau / hop dong cu the
        |
   +----|--------+-------------+
   |    |        |             |
   v    v        v             v
 parties results consents  settlements
 (ai choi)(ket qua)(dong y?)(thanh toan)

  point_balances       <-- So du point cua moi user
  public_ledger        <-- VIEW tong hop (read-only, cho public)


2.2 ENUM Types
--------------

  contract_type:        rps | work_reward | tournament | custom
  contract_status:      created | active | completed | disputed | resolved | settled
  payment_type:         ix_point | ix_free_point | both
  point_type:           ix_point | ix_free_point
  chain_record_policy:  required | optional | off
  result_source:        system | user

4. API DESIGN

4.1 Overview
------------

Supabase tu tao REST API cho moi table. FE goi truc tiep qua HTTP.

  Endpoint                Methods                 Mo ta
  -----------------------------------------------------------------------
  /contract_templates     GET POST PATCH DELETE    Templates (Admin)
  /contract_instances     GET POST PATCH DELETE    Instances
  /contract_parties       GET POST PATCH DELETE    Parties
  /contract_results       GET POST PATCH DELETE    Results
  /contract_consents      GET POST PATCH DELETE    Consents
  /contract_settlements   GET POST PATCH DELETE    Settlements
  /point_balances         GET POST PATCH DELETE    Balances
  /public_ledger          GET                      Public view (read-only)
  /rpc/register_player    POST                     Dang ky player
  /rpc/create_contract    POST                     Tao contract
  /rpc/join_contract      POST                     Join contract
  /rpc/activate_contract  POST                     Activate contract
  /rpc/settle_contract    POST                     Settle contract

  QUAN TRONG: Cac thao tac business logic (tao, join, activate, settle)
  -> goi RPC (muc 4). Khong POST/PATCH truc tiep vao tables.


4.2 Query Syntax (cho GET requests)
------------------------------------

  Filtering:
    eq    =          ?status=eq.active
    neq   !=         ?type=neq.custom
    gt    >          ?balance=gt.100
    gte   >=         ?fee_rate=gte.5
    lt    <          ?balance=lt.50
    lte   <=         ?escrow_amount=lte.1000
    in    IN         ?status=in.(created,active)
    is    IS NULL    ?tx_hash=is.null
    like  LIKE       ?name=like.*Casual*
    ilike ILIKE      ?name=ilike.*casual*

  Select:
    ?select=id,name,type,fee_rate
    ?select=*,contract_templates(name,type)         // JOIN relations

  Order:
    ?order=created_at.desc

  Pagination:
    ?limit=20&offset=0
    Header: Prefer: count=exact  ->  Response: Content-Range: 0-19/156

5.4 activate_contract
---------------------

    "p_contract_id": "30000000-0000-0000-0000-000000000001"
  }

  Param           Type   Required   Mo ta

5.5 settle_contract
-------------------
  Thanh toan — chuyen point cho winner, thu phi.

  POST /rest/v1/rpc/settle_contract

  Request:
  {
    "p_contract_id": "30000000-0000-0000-0000-000000000001"
  }

  Param           Type   Required   Mo ta
  p_contract_id   uuid   Yes        Contract nao

  Noi bo:
    1. Doc result (is_final=true)
    2. Tinh:
       - total_escrow = tong escrow_amount cac parties
       - fee = total_escrow x fee_rate / 100
       - winner_amount = total_escrow - fee
    3. Neu draw: refund het, fee = 0
    4. Tao settlement records:
       - reward: Escrow -> Winner
       - fee: Escrow -> Treasury
       - refund: Escrow -> User (neu draw)
    5. Cap nhat point_balances
    6. Status -> settled, set settled_at

  Vi du thuc te (2 players x 60 pts, fee 5%):
    Settlement  From              To      Amount  Fee
    reward      Escrow(000...000) Winner  114.0   6.0

6. REALTIME SUBSCRIPTIONS
================================================================

  FE subscribe WebSocket de nhan live updates:

    // Theo doi trang thai 1 contract

      .channel('my-contract')
      .on('postgres_changes', {

        // payload.new.status -> 'active', 'completed', 'settled'...

      .subscribe()

      }, (payload) => {

      })
      .subscribe()

      .channel('my-balance')
      .on('postgres_changes', {
        event: 'UPDATE',
        schema: 'public',
        table: 'point_balances',
        filter: `user_id=eq.${userId}`
      }, (payload) => {
        // payload.new.balance -> so du moi
      })
      .subscribe()

    400  Bad Request     Sai params
    401  Unauthorized    Token het han -> refresh

    "details": null,
    "hint": null,
    "message": "The result contains 0 rows"
  }

    const { data, error } = await supabase.rpc('join_contract', { ... })

    if (error) {
      // error.message co the la:

10.1 Blockchain Recording — Hien thi theo policy
-------------------------------------------------

  He thong ghi blockchain co 2 cap:
  Admin dat policy tren template -> User chon khi join (neu optional).

  FE can hien thi khac nhau tuy chain_record_policy cua template:

    Policy      FE hien thi                                          User interaction
    ----------  ---------------------------------------------------  ----------------------------
    required    Notice: "Hop dong nay se duoc ghi tren blockchain"   Khong co toggle, chi thong bao
    optional    Toggle/checkbox: "Ghi hop dong len blockchain"       User bat/tat -> truyen vao
                + text tu chain_record_description                   p_chain_record_choice khi join
    off         KHONG HIEN THI GI                                    Khong co

  Logic xac dinh chain_record tren instance:

    Template Policy   User Choice          chain_record
    ----------------  -------------------  ------------
    required          (khong co)           true
    optional          true                 true
    optional          false                false
    optional          null (khong chon)    false
    off               (khong co)           false

  Luu y: Chon ghi on-chain co the phat sinh phi gas (TBD).
         Thay doi policy KHONG anh huong cac contract da tao, chi ap dung cho contract moi.


10.2 Contract Lifecycle — Hien thi trang thai
----------------------------------------------

    Created   -> "Dang cho nguoi choi"
    Active    -> "Dang dien ra"
    Completed -> "Da co ket qua — cho xac nhan"
    Disputed  -> "Dang khieu nai — cho admin xu ly"
    Resolved  -> "Khieu nai da giai quyet — cho thanh toan"
    Settled   -> "Da hoan tat"


10.3 Result & Consent Flow — FE can xu ly
------------------------------------------

  Normal Flow:
    1. Server bao ket qua   -> FE nhan realtime update (status -> completed)
    2. Hien thi ket qua     -> "Ban thang/thua/hoa"
    3. Hien thi nut         -> [Dong y ket qua] hoac [Khieu nai]
    4. User nhan Dong y     -> POST /contract_consents { consented: true }
    5. Ca 2 dong y          -> Co the settle
    6. Neu timeout (timeout_seconds tu template conditions)
       -> Tu dong consent (backend xu ly)

  Dispute Flow:
    1. User nhan Khieu nai  -> Hien thi form nhap ly do
    2. Submit               -> POST /contract_consents { consented: false, reason: "..." }
    3. Status -> disputed   -> Hien thi: "Dang cho admin xu ly"
    4. Admin resolve        -> Status -> resolved -> settled
    5. FE nhan realtime     -> Hien thi ket qua cuoi cung


10.4 Public Ledger — Hien thi cong khai
-----------------------------------------

  Trang public ledger can hien thi:
    Contract ID:             ID (co the rut gon)
    Contract type:           RPS, Work Reward, Tournament...
    Parties:                 User IDs (can nhac an danh — TBD)
    Point transfer amount:   So IX Points / Free Points chuyen
    Timestamps:              Thoi diem moi lan doi trang thai
    Result / Status:         Trang thai hien tai va ket qua cuoi


10.5 Admin Dashboard — Template Management
--------------------------------------------

  Man tao/sua template can:
    - Form fields cho tat ca columns trong contract_templates
    - Section "Blockchain Recording":
      - Radio button hoac select: required / optional / off
      - Khi chon optional: hien thi them text field cho chain_record_description
    - Chi Admin moi duoc tao/sua template


10.6 Settlement Calculation
---------------------------

  Total Escrow = tong escrow_amount cua tat ca parties
  Fee          = Total Escrow x (fee_rate / 100)
  Winner Gets  = Total Escrow - Fee

  Vi du: 2 players x 50 pts, fee_rate = 5%
    Total Escrow = 100
    Fee          = 100 x 0.05 = 5
    Winner Gets  = 100 - 5 = 95
    Treasury     = 5

  Neu Draw (va draw_refund = true):
    Refund moi player = escrow_amount goc
    Fee = 0
