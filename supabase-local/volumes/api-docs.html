Authentication

All API requests require the apikey header:

curl -H "apikey: YOUR_ANON_KEY" \
     -H "Authorization: Bearer YOUR_ANON_KEY" \
     http://localhost:8000/rest/v1/your_table

Two types of keys:

KeyRoleUsage
ANON_KEYanonClient-side, respects RLS policies
SERVICE_ROLE_KEYservice_roleServer-side, bypasses RLS (admin)

REST API — Auto-generated from Database Tables

PostgREST automatically creates REST endpoints for every table in the public schema.

Create a table → API endpoint appears automatically. No code needed.

CRUD Operations

MethodEndpointDescription
GET/rest/v1/{table}Select rows (with filtering, pagination)
POST/rest/v1/{table}Insert rows
PATCH/rest/v1/{table}?column=eq.valueUpdate rows matching filter
DELETE/rest/v1/{table}?column=eq.valueDelete rows matching filter

Filtering & Querying

OperatorExampleDescription
eq?status=eq.activeEqual
neq?status=neq.settledNot equal
gt / gte?amount=gt.100Greater than (or equal)
lt / lte?amount=lt.1000Less than (or equal)
in?status=in.(active,completed)In list
is?tx_hash=is.nullIs null
like?name=like.*RPS*Pattern match
order?order=created_at.descSort results
limit?limit=10&offset=0Pagination
select?select=id,name,statusSelect specific columns

Examples

# Get all active contract templates
curl "http://localhost:8000/rest/v1/contract_templates?is_active=eq.true" \
  -H "apikey: ANON_KEY"

# Get contract instances with status 'active', sorted by newest
curl "http://localhost:8000/rest/v1/contract_instances?status=eq.active&order=created_at.desc" \
  -H "apikey: ANON_KEY"

# Insert a new contract template (admin)
curl -X POST "http://localhost:8000/rest/v1/contract_templates" \
  -H "apikey: SERVICE_ROLE_KEY" \
  -H "Authorization: Bearer SERVICE_ROLE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "RPS Match", "type": "rps", "fee_rate": 5.0}'

# Update contract status
curl -X PATCH "http://localhost:8000/rest/v1/contract_instances?id=eq.UUID_HERE" \
  -H "apikey: SERVICE_ROLE_KEY" \
  -H "Authorization: Bearer SERVICE_ROLE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"status": "active"}'

# Get public ledger view
curl "http://localhost:8000/rest/v1/public_ledger?order=created_at.desc&limit=50" \
  -H "apikey: ANON_KEY"

Auth API — GoTrue

User authentication, registration, and session management.

Endpoints

MethodEndpointDescription
POST/auth/v1/signupRegister new user
POST/auth/v1/token?grant_type=passwordLogin with email/password
POST/auth/v1/token?grant_type=refresh_tokenRefresh access token
POST/auth/v1/logoutLogout (invalidate token)
GET/auth/v1/userGet current user info
PUT/auth/v1/userUpdate user (email, password, metadata)
POST/auth/v1/recoverSend password recovery email
POST/auth/v1/magiclinkSend magic link email
POST/auth/v1/otpSend OTP (phone/email)
POST/auth/v1/verifyVerify OTP
GET/auth/v1/settingsGet auth settings (public)
POST/auth/v1/admin/usersCreate user (admin)
GET/auth/v1/admin/usersList users (admin)
GET/auth/v1/admin/users/{id}Get user by ID (admin)
PUT/auth/v1/admin/users/{id}Update user (admin)
DELETE/auth/v1/admin/users/{id}Delete user (admin)

Examples

# Sign up
curl -X POST "http://localhost:8000/auth/v1/signup" \
  -H "apikey: ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "password123"}'

# Login
curl -X POST "http://localhost:8000/auth/v1/token?grant_type=password" \
  -H "apikey: ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "password123"}'

# Get current user (with access token from login)
curl "http://localhost:8000/auth/v1/user" \
  -H "apikey: ANON_KEY" \
  -H "Authorization: Bearer ACCESS_TOKEN"

# Admin: list all users
curl "http://localhost:8000/auth/v1/admin/users" \
  -H "apikey: SERVICE_ROLE_KEY" \
  -H "Authorization: Bearer SERVICE_ROLE_KEY"

S3-compatible file storage for uploads, downloads, and management.

MethodEndpointDescription

GET/storage/v1/bucket/{id}Get bucket details
PUT/storage/v1/bucket/{id}Update bucket
DELETE/storage/v1/bucket/{id}Delete bucket
POST/storage/v1/bucket/{id}/emptyEmpty bucket

File Operations

MethodEndpointDescription
POST/storage/v1/object/{bucket}/{path}Upload file
GET/storage/v1/object/{bucket}/{path}Download file
PUT/storage/v1/object/{bucket}/{path}Update file
DELETE/storage/v1/object/{bucket}/{paths}Delete file(s)
POST/storage/v1/object/list/{bucket}List files in bucket
POST/storage/v1/object/moveMove file
POST/storage/v1/object/copyCopy file
GET/storage/v1/object/public/{bucket}/{path}Get public URL
POST/storage/v1/object/sign/{bucket}/{path}Create signed URL

Examples

# Create a bucket
curl -X POST "http://localhost:8000/storage/v1/bucket" \
  -H "apikey: SERVICE_ROLE_KEY" \
  -H "Authorization: Bearer SERVICE_ROLE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"id": "avatars", "name": "avatars", "public": true}'

# Upload a file
curl -X POST "http://localhost:8000/storage/v1/object/avatars/user1.png" \
  -H "apikey: ANON_KEY" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: image/png" \
  --data-binary @photo.png

# List files
curl -X POST "http://localhost:8000/storage/v1/object/list/avatars" \
  -H "apikey: ANON_KEY" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"prefix": "", "limit": 100}'

Realtime — WebSocket Subscriptions

Subscribe to database changes in real-time via WebSocket. No REST API — uses WebSocket protocol.

Connection

WebSocket URL: ws://localhost:8000/realtime/v1/websocket?apikey=ANON_KEY&vsn=1.0.0

JavaScript Client Example

import { createClient } from '@supabase/supabase-js'

const supabase = createClient('http://localhost:8000', 'ANON_KEY')

// Subscribe to contract status changes
supabase
  .channel('contract-updates')
  .on('postgres_changes',
    { event: 'UPDATE', schema: 'public', table: 'contract_instances' },
    (payload) => {
      console.log('Contract updated:', payload.new.id, payload.new.status)
    }
  )
  .subscribe()

// Subscribe to new results
supabase
  .channel('results')
  .on('postgres_changes',
    { event: 'INSERT', schema: 'public', table: 'contract_results' },
    (payload) => {
      console.log('New result:', payload.new)
    }
  )
  .subscribe()

Edge Functions — Deno Serverless

Custom server-side logic written in TypeScript/JavaScript, running on Deno.

Invoke Function

MethodEndpointDescription
POST/functions/v1/{function_name}Invoke an edge function

Example

# Invoke a function
curl -X POST "http://localhost:8000/functions/v1/my-function" \
  -H "apikey: ANON_KEY" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "world"}'
Functions are stored in volumes/functions/. Each subfolder = one function. The main function is the entry point.
